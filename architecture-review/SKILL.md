# Architecture Review

结构化架构评审，产出分析文档。

## 评审框架

### 1. C4 模型视角

| 层级 | 关注点 |
|------|--------|
| Context | 系统边界、外部依赖、用户角色 |
| Container | 服务划分、数据存储、通信方式 |
| Component | 模块职责、接口设计、依赖方向 |
| Code | 类设计、设计模式、代码质量 |

### 2. 质量属性评估

| 属性 | 评估维度 |
|------|---------|
| 性能 | 吞吐量、延迟、资源利用率 |
| 可用性 | SLA、故障恢复、降级策略 |
| 可扩展性 | 水平扩展、数据分片、无状态设计 |
| 安全性 | 认证授权、数据加密、审计日志 |
| 可维护性 | 模块耦合、代码可读性、文档完整性 |
| 成本 | 资源成本、运维成本、技术债务 |

### 3. ADR（架构决策记录）

使用 [[adr]] 模板。`status` 从 proposed → accepted。决策变更不改旧记录，新建 ADR 并旧记标 superseded。

### 4. 架构评审报告

使用 [[architecture]] 模板。评审发现的风险与改进建议写入 `Open Questions` 章节，决策后迁移至新 ADR。

## 评审原则

- **关注约束** — 技术选型受业务/团队/时间约束，不追求完美
- **量化评估** — 用数据而非直觉判断性能/可用性
- **渐进改进** — 优先解决高风险问题
- **记录决策** — ADR 记录"为什么"，方便未来回顾
