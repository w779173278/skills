# Knowledge Distillation

将复杂技术内容蒸馏为原子化、聚焦的知识笔记。

## 核心原则

1. **一个笔记解决一个问题** — 每个笔记只覆盖一个概念/主题
2. **自包含** — 笔记本身可独立理解，不依赖上下文
3. **交叉引用** — 通过 wikilink `[[笔记名]]` 关联相关概念
4. **分层组织** — 概念层(10-概念) → 系统层(20-系统) → 项目层(50-项目)

## 工作流程

### Step 1: 分析源文档

读取目标文档，识别：
- 核心概念（可独立成篇的知识点）
- 代码示例（归属于哪个概念）
- 概念间的依赖关系

### Step 2: 拆分策略

| 源文档类型 | 拆分方式 |
|-----------|---------|
| 教程型（步骤序列） | 按阶段拆分，每篇一个阶段 |
| 概念型（多个概念混杂） | 每个概念独立成篇 |
| 架构型（系统设计） | 概念层 + 实现层分离 |
| 大型笔记(>500行) | 提取子概念到 10-概念/，系统笔记保留概览 |

### Step 3: 笔记格式

按内容类型选用对应模板：

| 内容类型 | 模板 |
|---------|------|
| 原子概念 | [[concept]] |
| 系统/框架 | [[system]] |
| 架构设计 | [[architecture]] |
| 决策记录 | [[adr]] |

### Step 4: 归档原文

将拆分前的原始大笔记移至 `99-归档/` 目录：
```
99-归档/原始笔记名（已拆分）.md
```

## 目录映射

| 内容类型 | 目标目录 |
|---------|---------|
| 原子概念 | `10-概念/{领域}/` |
| 系统/框架笔记 | `20-系统/{系统名}/` |
| 架构设计 | `30-架构/` |
| 项目文档 | `50-项目/{项目名}/` |
| 已拆分原文 | `99-归档/` |

## 质量检查

拆分完成后验证：
- [ ] 每个笔记 < 400 行
- [ ] 有完整的 frontmatter
- [ ] 有 `## 概述` 和 `## 小结`
- [ ] wikilink 引用有效
- [ ] 原文已归档
